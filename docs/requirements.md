## 1. 소개

### 1.1 목적

본 문서는 그룹 정산 관리 시스템 **GroupPay**의 소프트웨어 요구사항을 정의한다.
본 문서는 개발팀, 이해관계자 간의 요구사항 합의 기준선으로 활용되며,
이후 설계, 구현, 테스트 단계의 입력물로 사용된다.

### 1.2 범위

GroupPay는 여행, 모임 등에서 발생하는 공동 지출을 기록하고,
최소 송금 횟수로 정산 결과를 산출하는 웹 서비스이다.
별도 회원가입 없이 UUID 기반 링크 공유로 그룹에 접근하며,
그룹 내 지출 등록부터 최종 정산 결과 확인까지의 흐름을 지원한다.

### 1.3 정의 및 약어

| 용어           | 정의                                                                      |
| -------------- | ------------------------------------------------------------------------- |
| 그룹           | 정산의 단위. 하나의 여행/모임에 대응                                      |
| 멤버           | 그룹에 속한 참여자                                                        |
| 방장           | 그룹 생성 시 설정한 PIN을 통해 인증된 사용자. 정산 확정 등 관리 권한 보유 |
| 일반 참여자    | PIN 인증 없이 링크로 접속한 사용자. 지출 등록/조회 가능                   |
| PIN            | 그룹 생성 시 설정하는 4자리 숫자. 방장 권한 인증에 사용                   |
| 지출           | 멤버 중 한 명이 대신 낸 비용                                              |
| 정산 확정      | 방장이 지출 등록을 마감하고 정산 결과를 고정하는 행위                     |
| 순잔액         | 한 멤버가 받아야 할 금액 - 줘야 할 금액                                   |
| 정산 받는 멤버 | 순잔액이 양수인 멤버 (돈을 받아야 하는 사람)                              |
| 정산 하는 멤버 | 순잔액이 음수인 멤버 (돈을 줘야 하는 사람)                                |
| UUID           | 그룹 식별 및 링크 공유에 사용하는 고유 식별자                             |
| OPEN           | 지출 수정이 가능한 그룹 상태                                              |
| SETTLED        | 정산이 확정되어 수정 불가한 그룹 상태                                     |

## 2. 전체 설명

### 2.1 제품 개요

```
그룹 생성 (그룹명 + PIN 4자리 설정) → UUID 링크 공유 → 멤버들이 링크로 접속
    ↓
지출 등록/수정/삭제 (OPEN 상태, 누구나 가능)
    ↓
방장으로 전환하기 → PIN 입력 → 방장 권한 활성화
    ↓
방장이 "정산하기" 실행
    ↓
정산 확정 (SETTLED 상태, 수정 불가)
    ↓
최소 송금 결과 조회 + 정산 받는 멤버 계좌번호 복사
```

### 2.2 그룹 상태 전이

GroupPay의 핵심 상태는 두 가지이며, 단방향으로만 전이된다.

```
[생성] → OPEN ──────────────→ SETTLED
              (방장만: 정산하기)
```

- **OPEN**: 지출 등록/수정/삭제 가능, 멤버 추가/제거 가능
- **SETTLED**: 모든 수정 불가, 정산 결과 조회만 가능
- SETTLED → OPEN 복귀는 지원하지 않는다 (정산 확정은 되돌릴 수 없음)

### 2.3 사용자 특성

- 별도 회원가입 없이 UUID 링크로만 그룹에 접근한다
- 링크 접속자는 일반 참여자로, PIN 인증 시 방장 권한을 획득한다
- 비기술 사용자도 별도 안내 없이 사용할 수 있어야 한다

## 7. 가정 및 의존성

### 가정

- 사용자는 UUID 링크를 외부 메신저 등을 통해 직접 공유한다
- PIN은 그룹 생성자가 참여자들과 별도로 공유하거나 직접 보관한다
- PIN 인증은 해당 브라우저 세션 동안만 유지되며, 세션 만료 시 재인증이 필요하다

### 의존성

- 웹 브라우저 환경에서 동작하며, 클립보드 접근 권한이 필요하다 (계좌번호 복사 기능)
